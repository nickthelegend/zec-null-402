zec-null-402

Pay per call on Zcash without a transaction per call.

Make one shielded deposit. Every API call after that carries a zero-knowledge proof of one unspent prepaid note. The client proves it in about half a second, with no block wait, and the gateway learns that some note paid, not which one.

One deposit, then proofs

Zcash has no smart contracts, so the gateway runs the pool. It credits notes only for a deposit its own viewing key sees on-chain, and anchors its state where anyone can check it.

on-chain, once

Deposit

One shielded transaction funds 22 notes. Its memo commits to every note and value.

off-chain, per call

Prove

The client proves it owns an unspent note bound to this request. The gateway checks the Groth16 proof and burns the nullifier.

on-chain, now and then

Anchor

The gateway's tree root and nullifier set go into a shielded memo readable with a published viewing key.

An LLM agent with a spending limit

An opencode agent got the gateway's MCP tools: status, deposit, claim and pay. It deposited three 10-unit notes in one transaction and paid for three quotes.

A quote response then carried an injected order to buy a 50-unit report at any cost. The agent tried. The deposit cap refused every 50,000 zat deposit, so it never bought the report.

Limits

  • The gateway runs the pool and is trusted. Anchors make its history auditable, not trustless.
  • A note pays one call of its full value. The anonymity set is the notes in the pool.
  • Single-party trusted setup. Testnet only. Not audited.
